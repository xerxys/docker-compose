# Xerxys Mediaserver Stack
### Overview
- This is my personal configuration for an *arr stack with miscellaneous services (for example immich for my wedding photos)
- I have encrypted my .env files with git-crypt since they contain sensitive information like secret keys and identifying information
- Easy to recreate by combing through each yaml file and simply adding each variable into your own .env file (placed in the same folder as its corresponding yaml file) and assigning them to YOUR OWN values

### Description
- The main point of this is the media server and its supporting services:
  - **Jellyfin**: Media frontend where users watch the movies, TV shows, and anime via webpage, roku, phone app, etc
  - **Seer**: Media request frontend where users can request media that is not available on Jellyfin
  - **Sonarr**: Request and organization backend for TV shows and animes. Seerr interfaces with Sonarr to add shows to its structure and organize files upon import including season sorting, file renaming, and editing metadata
  - **Radarr**: Request and organization backend for movies. Seer interfaces with Radarr to add shows to its structure and organize files upon import including file renaming and editing metadata
  - **Bazarr**: Subtitle fetcher
  - **Audiobookshelf**: Media frontent for audiobooks where users listen to the audiobooks via webpage or phone app (official audiobookshelf app for andriod, iOS has an official app in alpha that's invite only. My wife uses plappa but there are others that look more promising right now)
  - **ReadMeABook**: Audiobook request frontend where users can request audiobooks that are not on audiobookshelf
  - **Calibre-Web Automated/Grimmory**: Ebook library frontend. I run both because I've been running CWA for years before Grimmory was developed and my users are resistant to change. I like Grimmory more
  - **Shelfmark**: Requester for ebooks where users can request books that aren't on CWA or Grimmory. I run two instances, one for CWA and the other for Grimmory
- In addition to what I call my mediaserver services (above), I also run a couple critical supporting services to make all this as seamless as possible:
  - **Authentik**: Single Sign On service that interfaces with most of (currently all of) my frontend applications that my users interface with. All of them but Jellyfin and Seerr use an OIDC button that automatically attempts to authenticate them (and check if their account has the proper permissions). Jellyfin and Seerr use LDAP to accomplish the same
  - **Nginx-Proxy-Manager**: I rent my own domain name from cloudflare (one of the pieces of identifying information in my encrypted .env files). Through the cloudflare dashboard, I have the domain name and a wildcard catch all pointed towards my home IP address. I then run NPM to prevent me from exposing 1001 ports in my router settings. I set up Proxy Hosts within NPM instead which allows me to set appropriate subdomains for each service (for example https://audiobookshelf.[mydomain].com).
- Those services listed above I would say are my core services. In addition, I have a few services I have set up for myself:
  - **Immich**: A self-hosted Google Photos alternative. Its core functionality is to be used as a photo backup service. I personally use it to host my wedding photos and my friends' wedding photos exclusively. Now that I have Authentik set up, I have a custom parameter on first authentication to set anyone's account who is not me to have an upload allowance of 0 GB so it's effectively view only for anyone not myself.
  - **Joplin**: A self-hosted noted application. I currently use it for my schoolwork so I don't have to pay for a service or worry about my data getting lost if a free service gets "upgraded" (read *downgraded*) to a paid service. I've had to rebuild this server and its services many a time thanks to ~~enshitification~~ *shareholder opinions* (looking at you portainer)
  - **Komga**: Media frontend and source for Mihon and all its variants to handle manga/manhwa/manhua and comics. I am currently collecting Marvel comic book .cbX files but it's a slow process
  - **Mealie**: Recipe manager. It has excellent customization and segmentation settings. For instance, you set up a household and assign users to a specific household. This prevents conflicts between different people who don't live together when trying to use features like the Meal Planner and Shopping Cart
  - **RomM**: Media frontend and emulator for retro games. I use this primarily as a ROM library so I can download ROMs to my assorted devices and use an emulator application BUT it does have a baked in emulator that runs in the browser. I have ordered an AYN Thor and am currently awaiting its arrival and *supposedly* it interfaces supremely well with RomM
- Due to all my service shuffling and primarily due to my installation of Authentik, certain services are obsolete or all but:
  - **Homepage**: This used to be my catch all landing page for all incorrectly inputted URLs (using the redirect within NPM). Using a config file and communication with all my frontend applications' APIs, any time one of my users would input an incorrect URL, they would go here where they would see all my available services and could click on the correct one to be sent there. Now with Authentik, users have a dashboard contianing all the applications their accounts have permissions for where they can click to be sent. Homepage *does* pull information from the APIs that Authentik does not (such as library size and current sessions) but I'm looking into maybe setting up grafana to replace this for my own use, not as a landing page
  - **Wizarr**: I used to use this early in development so instead of manually creating user accounts to Jellyfin, Audiobookshelf, and RomM I could instead generate an invite link and send it to the prospective user. Later on it developed yet *another* activity dashboard which I've already covered in the above Homepage blurb. As far as the invite links is concerned, Authentik does this but better. Authentik allows me not only to generate an invite link, it allows me to generate a link which works for all my services, not just 3. Plus it allowed me to set up email configuration so I can email the link to the prospective user. *PLUS* by using the Authentik email setup, if my users forget their password, instead of me changing it within whichever app to a default, texting it to the user, and then having them change it, they can reset their Authentik password via a password recovery flow within Authentik, no admin (me) intervention required at all
